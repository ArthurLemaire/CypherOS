## V2EX · 分享创造

节点 /go/create。写给开发者看：讲清楚它是什么、怎么做的、哪里还不行。Markdown 可用，链接可以点。配图两张：卡片 5 和卡片 6，或者真机截图 `approval` 和 `hands-stage`。

标题：

```
nanoMuse：完全开源的 Muse 式个人智能体，跑在 Android 手机上（GPL-3.0）
```

正文：

```
Meta 这个月发了 Muse：一个有名字、有脸的个人智能体，替你办事，后台一直在干，记得你，遇到删不回来的事先问你。样子很好，但它是一个服务——每个用户一台 Meta 云上的虚拟机，iOS/Android/网页/WhatsApp 都是它的客户端，模型是 Meta 的，碰不到你的手机。

我们把这个样子做成了开源软件，整个 agent 跑在手机上：nanoMuse。

**它是什么**

- Android App，基于 OpenMinis 1.13（GPL-3.0）用 git subtree 引进来改的。OpenMinis 已经把手机上的 agent 运行时做好了：proot 里的 Alpine Linux、shell、WebView 浏览器、MCP、技能、定时任务、无障碍执行器，模型用任何 OpenAI 兼容接口。我们在它上面做 Muse 的那一层：一个主对话、有名字和脸的 agent、每天写给你的动态、按时检查的目标、能看能改的记忆文件，还有一道审批。
- 审批（RiskGate）：shell 命令和浏览器动作先分类——删除、发送、付款、安装——命中就停下来出卡片：允许一次 / 本次对话 / 对这个目录、收件人、域名总是允许 / 拒绝。授权按范围记住，在「权限」里能撤。密码和验证码永远不代输。
- 动手操作屏幕（0.1.12）：没有 API 的 App，agent 看一张截图、做一个动作、再看一张。我们用截图而不是无障碍树：国内 App 的树要么是空的 WebView，要么是一堆无名节点，而截图是视觉模型本来就会看的东西。无障碍服务只负责截图和注入手势，不读内容。技能、CLI、MCP、浏览器排在前面，屏幕排最后；默认关闭，登录和验证码交还给你，同一套审批。0.1.15 加了「舞台」：屏幕边缘的光晕、要点的位置上转着的环、落下去的涟漪，能看见它在做什么。
- 电脑（0.1.13）：电脑上跑一个标准库的 Python 文件 host/nanomuse_host.py，打印地址和六位配对码，App 里填上。之后手机上的一句话可以在电脑上跑命令、取放文件、开网页、看一眼屏幕，结果和审批回到手机。单向，手机操作电脑，电脑碰不到手机；只走局域网。
- 模型自己带：对话、图像、视频三个，一把阿里云百炼的 key 全配好，或者每个各用一家。没有服务器，不用账号。

**哪里还不行**

- 操作屏幕每一步发一张截图给视觉模型，慢，也不便宜；小一点的视觉模型够用。需要 Android 11+，因为无障碍截图 API 是那时才有的。
- host 这版没有 TLS，只在你信任的网络里用。
- 每一版都是从 tag 构建的 APK，手动安装，不上商店。国产 ROM 的后台限制各家不同，电池和自启动要自己放开。
- 还没有 iOS 和桌面 App。接下来按这个顺序：桌面 App、iOS、部署在自己机器上的网页版、眼镜。

**代码**

- 仓库：https://github.com/nano-muse/nanoMuse （GPL-3.0-or-later；OpenMinis 上游的改动都标了 `// nanoMuse:`，上游发版还能合）
- 主页和下载：https://nanomuse.cn
- 现在是 0.1.15。用它做一件真实的事，什么坏了发 issue，比 star 有用。

nanoMuse 是独立的社区项目，与 Meta 无关；Muse 是 Meta 的商标。
```

## 知乎

先答题，后发文。在「怎么看 Meta 发布的个人 AI 智能体 Muse」「有哪些开源的手机端 AI Agent」这类问题下回答；开头就说明是项目自己的人。文章版等公众号那篇写完直接改。

```
利益相关：我们在做 nanoMuse，一个完全开源的 Muse 式个人智能体，Android App。

Muse 最值得看的不是模型，是产品形态：一个智能体，不是一堆工具。有名字、有脸；第一次见面先聊一聊；每天有写给你的动态；目标在后台推进；记忆能看能改；删不回来的事先问你。这套东西过去两年大家都在聊，Muse 把它做成了一个完整的消费品。

但 Muse 是一个服务。每个用户一台 Meta 云上的虚拟机，手机、网页、WhatsApp 都是客户端；模型是 Meta 的，账号是 Meta 的，虚拟机里有浏览器，但碰不到你的手机，所以国内这些从来没有 API 的 App 它一个都够不着。

我们的判断是：这个形态值得有一个开源的、跑在自己设备上的版本。所以有了 nanoMuse。

三者放在一起看：

| | Meta Muse | OpenMinis | nanoMuse |

| 是什么 | 云服务，多端客户端 | 手机上的 agent 工作台 | OpenMinis 运行时上的 Muse 式智能体，自由软件 |
| 跑在哪 | Meta 的云虚拟机 | 装它的那台手机 | 手机；接下来是你的电脑 |
| 形态 | 一个有名字有脸的智能体，动态、目标、Sentinel | 会话、工具、设置 | 一个智能体，名字、脸、第一次对话、动态、目标、能改的记忆 |
```

## 评论回复的口径

回复用项目的口吻，但别端着；一个问题一段，能给数字就给数字，不知道就说不知道。

- **要花多少钱？** App 免费开源，钱花在你自己的模型 key 上。日常聊天、写动态、查目标用的是文字模型，很便宜；「动手操作屏幕」每一步发一张截图给视觉模型，是最费的一项，选小一点的视觉模型就省很多。具体多少看你选的服务商怎么定价，跑几次看一眼账单最准。
- **为什么要无障碍权限？会不会读我的屏幕？** 无障碍服务只做两件事：截图，和把点、输、滑注入进去。它不读无障碍树，不读屏幕上的文字。截图随对话存在手机里，只发给你自己配的模型。而且只在你打开「动手操作屏幕」之后才会用到，默认关着。
- **悬浮窗权限呢？** 用来显示操作时屏幕顶上的胶囊：第几步、正在做什么，还有一个一直在的「停止」。
- **让 AI 操作 App 会不会被封号？** 有可能。有的 App 对自动操作敏感，建议先用不重要的账号试，别一上来就跑主号。付款、发送、删除之前它都会先问你；登录和验证码永远你自己输。
- **数据去哪了？** 聊天内容发给你自己配的模型服务商，其他都留在手机里：文件、记忆、形象图、截图。我们没有服务器，也没有账号体系，看不到任何东西。
- **和 OpenMinis 什么关系？** 基于 OpenMinis 1.13 改的，用 git subtree 引进来，上游改动都标了 `// nanoMuse:`，上游发新版还能合。OpenMinis 是一个很好的手机端 agent 运行时和工作台；nanoMuse 在它上面做 Muse 那一层——一个有名字有脸的智能体，加审批、屏幕、电脑。感谢他们。
- **和豆包 / 千问 / Manus 有什么区别？** 那些是别人给你用的产品，跑在他们的服务器上，用他们的模型。nanoMuse 是你自己拥有的软件：跑在你手机上，模型你自己选，代码全开，GPL。
- **为什么截图而不是无障碍树？** 国内 App 的无障碍树经常是空的 WebView 或者一堆没名字的节点；截图是视觉模型本来就会看的东西，而且和你看到的一样。代价是慢和费钱，见第一条。
- **有 iOS 吗？桌面版呢？什么时候？** 还没有。顺序是桌面 App、iOS、部署在自己机器上的网页版、眼镜。不承诺时间，每做完一小步就发一版。
- **后台被杀怎么办？** 国产 ROM 的后台限制各家不一样，去电池和自启动设置里放开 nanoMuse；具体机型的问题发 issue，带上机型和系统版本。
- **能自己编译吗？** 能，CONTRIBUTING.md 和 android/BUILDING.md 写了。每个发布的 APK 都是从对应 tag 构建的。
- **为什么不上应用商店？** 这一阶段一个小版本一个 APK，节奏快，签名一把，覆盖安装。稳定到 0.2.0 之后再看。
- **Muse 是 Meta 的，你们这算什么？** 独立的社区项目，跟 Meta 没有关系，Muse 是他们的商标；我们做的是同一种形态的开源实现，代码一行都不是他们的。
- **有 bug / 某个 App 点不对。** 谢谢，发个 issue，带上机型、版本、那一步的截图（打码）。这一阶段最有用的就是这个。
