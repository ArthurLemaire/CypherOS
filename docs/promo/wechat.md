```
Meta 在九月发布了 Muse。抛开模型和参数，它最值得看的是产品的样子：不再是一个聊天框，而是一个智能体。它有名字，有一张脸；第一次见面先跟你聊几句；每天早上写几条动态给你；你定的目标它在后台盯着；它记得你；遇到删不回来的事，它先停下来问你。

这套东西过去两年大家都在聊，Muse 把它做成了一个完整的消费品。

但 Muse 是一个服务。每个用户在 Meta 的云上有一台虚拟机，手机、网页、WhatsApp 都是它的客户端；模型是 Meta 的，账号是 Meta 的。虚拟机里有一个浏览器，但它碰不到你的手机——国内这些从来没有 API 的 App，它一个都够不着。

我们觉得，这个样子值得有一个开源的、跑在你自己设备上的版本。于是有了 nanoMuse。
```

```
一、它是什么

一句话：一个完全开源的、Muse 式的个人智能体，面向你的所有设备。现在是 Android 版。

四件事定义了这个项目，四件都已经在 App 里了：

Muse 式。一个智能体，而不是一堆工具：有名字、有脸，第一次见面先聊一聊，每天有写给你的动态，目标在后台持续推进，记忆能看也能改，无法撤销的操作前先问你。

完全开源。整个仓库 GPL-3.0-or-later。没有闭源组件，不用注册账号，不用信任任何服务器，也不绑定任何模型。每个版本都从对应的 tag 构建、手动安装。Muse、豆包、千问是别人给你用的产品；nanoMuse 是你自己拥有的软件。

有没有 API 都能做。国内日常用的 App，大多从来没有 API。它会顺着一把梯子往上试：先是技能、命令行或者 MCP 服务，再是用你的登录态抓一页，再是应用内浏览器，最后在你允许之后直接操作手机屏幕——像你一样看、一样点。默认关闭，0.1.12 起。

多端协同。一个智能体，你的每台设备都是它的一双手、一个入口。在手机上说一句，事情在电脑上办好——0.1.13 起。之后是桌面 App、iOS、部署在你自己机器上的网页版，还有眼镜。

二、装上后的第一天

装好，添加一个模型——任何 OpenAI 兼容接口配你自己的 key——然后开始聊。

第一次对话不是一个「你好，我是 AI 助手」的固定开场。它先问你怎么称呼，再给自己起名字：按你说话的语言，提三个，你挑一个，或者自己起。我们录的这一段里，用户说自己叫老周，它提了「小知」「阿策」和第三个，老周点了小知。从那一刻起，页头上的名字就换成了小知，之后每条通知也都是小知发来的。

```
它的脸默认是一只奶黄色的小龙——静态图和短片都内置在 APK 里，不需要任何模型。它干活的时候会换姿势：工作、等你、开心、抱歉，跟着它正在做的事呼吸、点头、歪头。想换一张脸，一句话描述，你的图像模型画四张给你挑，App 再给它摆出每个状态的姿势；配了视频模型，每个状态就是一段循环短片。

然后是三个 Tab：动态、目标、点子和资料库。

动态是每天早上写给你的三到六条短帖，来自它对你的了解和你让它留意的事。想换个方向，说一句就行。目标在聊天里定下来——「这个月每周跑三次步，周日晚上问我进度」——之后它会在单独的会话里按时来问；例程在 App 关着的时候照样跑。跑一个长任务，到 200 步它会问你「还继续吗」，而不是草草收尾。

三、无法撤销的事，先问你

这是 Muse 里我们最认同的一条，也是 nanoMuse 从 0.1.4 起就有的东西。

删除、发送、付款、安装——它在执行之前先把命令分类；命中的，停下来出一张卡片：允许一次、本次对话都允许、对这个目录（或者这个收件人、这个域名）总是允许、拒绝。授权按范围记住，在「权限」页里随时能收回。

密码和验证码永远你自己输——这不是一个设置项，是它没有这项能力。付款按钮在它按下之前，一定先问你。

**【图 4】** `cards/shots/approval.webp`（审批卡片：允许 小知 删除 工作区 里的东西？）和 `cards/shots/approval-done.webp`（「搞定，build-old 目录已删除」），并排。

```
这套规则在它所有的手上都一样：手机里的终端、应用内浏览器、屏幕操作，还有后面要说的电脑。判定只有一处，不会因为换了一双手就少问一次。
```

四、没有 API 的 App

Muse 够不着你手机上的 App；OpenMinis 这类跑在手机上的 agent 靠的是无障碍树。我们两条路都试了，最后选了截图。

原因很实际：国内 App 的无障碍树要么是一个空的 WebView，要么是一堆没名字的节点。而截图是视觉模型本来就会看的东西，和你看到的一样。

所以 0.1.12 的「动手操作屏幕」是这样工作的：它看一张截图，决定一个动作——点、输、滑——做完，再看一张。无障碍服务只做两件事：截图，和把手势注入进去。它不读无障碍树，不读屏幕上的文字。

屏幕排在梯子的最后一级。技能、命令行、MCP、浏览器能办的，它先用它们，而且会在开始之前告诉你它打算用哪只手。遇到登录、验证码和受保护的页面，它把手机交还给你——「这一步请你自己完成，然后点继续」。付款、发送、删除之前，同一张审批卡片。

0.1.15 把这个过程做成了看得见的：它操作的时候，屏幕边缘有一圈呼吸的光——工作时是蓝的，等你时是琥珀色；它要点的位置上，一个红色虚线环转着，旁边写着动作的名字——「点击『搜索』」——然后手指落下，一圈涟漪。屏幕顶上有一个胶囊，写着第几步、正在做什么，还有一个一直在的「停止」。这些东西都不会出现在截图里，模型永远看不到它们。

它默认是关着的。打开需要三样东西：无障碍服务、悬浮窗权限，和一个能看图的对话模型。设置页会把这三项的状态列出来，都就绪了才让你打开总开关。
```

**【图 5】** `cards/shots/hands-settings.webp`（动手操作屏幕的设置页，四项就绪）。**【图 6】**（待拍）`07-hands` 的舞台截图：光晕、环、胶囊。**【动图 3】**（待拍）`film/out/vertical/hands.mp4` 截成 GIF。

```
两句实话。每一步发一张截图给视觉模型，慢，也不便宜——选一个小一点的视觉模型会省很多。有的 App 对自动操作敏感，先用不重要的账号试。这些都写在仓库里。

```
五、手机指挥电脑

0.1.13 起，手机上的一句话可以在电脑上办。

做法是这样的：在电脑上运行一个 Python 文件，host/nanomuse_host.py——一个文件，只用标准库，Linux、macOS、Windows 都行，不用安装任何东西。它会打印一个地址和一个六位数字的配对码，十分钟内在 App 里填上。之后跟手机说「在电脑上看看下载目录里最近的三个文件叫什么」，它就去电脑上看：跑命令、拿文件、放文件、开网页、看一眼屏幕，结果回到手机上。

审批也回到手机上。电脑上的命令和手机上的命令用同一套判定——删除、发送、付款先问你——问的地方永远是手机。

它是单向的：手机操作电脑，电脑永远碰不到手机。只走局域网，中间没有云。这一版还没有 TLS，只在你信任的网络里用。
```

**【图 7】** `cards/out/06-reach.png`（电脑图卡：配对页 + 终端），或 `cards/shots/computers.webp` 单张。**【动图 4】** `film/out/vertical/pair.mp4` 截成 GIF（输入地址和配对码，配对成功）。**【图 8】**（待拍）`08-reach` 的结果卡片。

```
配对、电脑列表、「在某台电脑上」这几件东西，是之后每一台设备都要复用的：桌面 App、iOS、部署在你自己机器上的网页版、眼镜。一个智能体，每台设备都是它的一双手、一个入口——不是一堆客户端连着云上的一台虚拟机。
```

```
六、模型和钱

nanoMuse 没有服务器，也没有账号体系。聊天内容只发给你自己配的模型；文件、记忆、形象图、截图都留在手机里。我们看不到任何东西——不是政策上不看，是架构上没有那个地方。

它用三个模型：对话模型，所有对话、动态、目标都跑在它上面；图像模型，画它的脸和你要的图；视频模型，可选，让脸动起来。最省事的做法是一把阿里云百炼的 key 三个全配——通义千问、qwen-image、MiniMax-H3 都在上面——也可以每个模型各用一家。任何 OpenAI 兼容接口都行。

钱花在你自己的 key 上，App 本身免费、开源。日常聊天、写动态、查目标用的是文字模型，很便宜；「动手操作屏幕」每一步发一张截图给视觉模型，是最费的一项。具体多少看你选的服务商怎么定价，跑几次看一眼账单最准。
```

**【图 9】** `cards/shots/models.webp`（图像与视频模型页）。**【图 10】** `cards/out/08-models.png`（你的模型图卡）。

```
七、它是怎么做出来的

nanoMuse 站在另一个自由软件项目上：OpenMinis。

OpenMinis 已经把「手机上的 agent 运行时」做好了——proot 里的一套 Alpine Linux、shell、WebView 浏览器、MCP、技能、定时任务、无障碍执行器，模型用任何 OpenAI 兼容接口，iOS 和 Android 都有。我们用 git subtree 把 1.13 版整个引进来，在它上面做 Muse 的那一层：一条主对话、一个有名字和脸的智能体、每天写给你的动态、按时检查的目标、能看能改的记忆文件、一道审批、屏幕这双手、电脑这条线。上游的改动都标了记号，OpenMinis 发新版还能合进来。

它的人格是一个文件。SOUL.md 是它是谁、什么风格；USER.md 是它对你的了解；GLOBAL.md 和日记是它记住的事；HEARTBEAT.md 是它什么时候醒来。都在「设置 → 系统文件」里，能看，能改，能删。别的助手对你的记忆，用「导入记忆」贴过来就行。
```

**【图 11】** `cards/shots/sysfiles.webp`（系统文件列表）和 `cards/shots/soul.webp`（SOUL.md 打开的样子），并排。**【图 12】** `cards/shots/memory.webp`（「记一下：我在北京做 Android 开发」→「记下了，老周」）。
