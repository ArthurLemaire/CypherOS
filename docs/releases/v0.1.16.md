# nanoMuse 0.1.16 · Palette

The image and video models are now picked the way the chat model is — from what your key can actually use — and drawing on Alibaba Cloud Model Studio works again.

## Fixed

- **Avatar and pictures on Alibaba Cloud Model Studio answered HTTP 404.** Model Studio's OpenAI-compatible host has no `images/generations` (the public one answers 404 to every model), so "change your avatar to…" and any picture asked for in the chat failed as soon as the key was on Model Studio. Drawing now goes through Model Studio's native endpoint — the one the poses already used — with the same key and model. qwen-image 2.x / 3.x / plus / max and wan-image all work.
- **The default image model did not match what the page said.** The catalogue's first image model (wan2.7-image-pro) was picked while the page recommended qwen-image-3.0-pro. The recommended model now wins whenever the provider has it.

## Added

- **Image and video models listed from your key.** Settings → Image & video models asks the provider which models this key has — the same `/models` call the chat models come from — keeps the ones that draw, and shows them as a list with the recommended one marked; pick one like you pick a chat model. For video, Model Studio does not list its video models, so the known ones (MiniMax-H3 and the Wan video family) are each checked against your key without making a video, and the ones that answer are listed. *Check again* re-asks; any other model name can still be typed.
- **Wan video models.** Besides MiniMax/MiniMax-H3, the avatar's clips and the clips you ask for can run on wan2.6 / wan2.5 / wan2.2 (`-i2v` from a picture, `-t2v` from words — whichever you pick, the sibling is used for the other job).

## Changed

- The Chinese avatar page says 形象 where it said 脸 (a "face" reads oddly for a whole figure).
- versionCode 17; installs over 0.1.15 without losing data.

## Install

Download `nanoMuse-0.1.16-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.16-arm64.apk.sha256`.

图像模型和视频模型现在和对话模型一样，从你的 key 真正能用的模型里选；阿里云百炼上画图也恢复了。

### 修复

- **百炼下换形象、画图报 HTTP 404。** 百炼的 OpenAI 兼容地址没有 `images/generations`（公共地址对任何模型都返回 404），所以 key 一放在百炼上，「把你的形象换成……」和对话里要的图片都会失败。现在画图走百炼的原生接口——摆姿势本来就走这条路——同一把 key、同一个模型。qwen-image 2.x / 3.x / plus / max 和 wan-image 都可以。
- **默认图像模型和页面说的不一致。** 之前选的是目录里排第一的图像模型（wan2.7-image-pro），页面却推荐 qwen-image-3.0-pro。现在只要服务商有推荐的那个，就用它。

### 新增

- **图像、视频模型按 key 列出来选。** 设置 → 图像与视频模型 会问服务商这把 key 有哪些模型——和对话模型用的是同一个 `/models` 接口——只留下能画图的，列成一张表，推荐的那个有标记，像选对话模型一样点一下就行。视频这边百炼的接口不列视频模型，所以把已知的几个（MiniMax-H3 和通义万相视频系列）逐个拿你的 key 试一遍——不会真的生成视频——能用的列出来。「重新检查」会再问一次；其他模型名照旧可以手动填。
- **通义万相视频模型。** 除了 MiniMax/MiniMax-H3，形象的短片和你要的短视频也可以跑在 wan2.6 / wan2.5 / wan2.2 上（`-i2v` 从图片出发，`-t2v` 从文字出发——不管你选的是哪个，另一种任务自动用它的兄弟模型）。

### 变更

- 形象页里几处「脸」改成了「形象」（一整个小人，说「脸」不太顺）。
- versionCode 17；覆盖安装 0.1.15 不丢数据。

### 安装

下载 `nanoMuse-0.1.16-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.16-arm64.apk.sha256`。
