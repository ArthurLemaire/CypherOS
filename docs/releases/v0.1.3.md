# nanoMuse 0.1.3 · Home

The app opens on a conversation, not a list. One main chat with the face at the top, side chats in a drawer, and a bottom bar with Ideas, Goals and Library — the shape of Muse on a phone. Everything OpenMinis had is still there; it is reached from these pages instead of the old session list.

## Added

- **Home.** On phones in portrait the start route renders the nanoMuse home: a four-tab shell (chat, ideas, goals, library) whose chat pane stays composed under the other tabs, so switching tabs keeps the scroll position, the composer draft and a running stream. Tablets and landscape keep OpenMinis' two-pane layout unchanged. Deep links and notifications still open a full-screen chat on top.
- **Main chat.** The first session becomes the main chat and is remembered; it is what the app opens on and what the chat tab returns to. Its header is Muse's: the face on a pale disc, the name pill hanging off its chin, a round menu button on the left and a round ⋯ on the right. Side chats get the compact header — title, menu, ⋯ — and take their title from the first exchange, as before.
- **The drawer.** Agent name, *Main chat*, the side-chat list with search, an archive glyph that opens the full session list (OpenMinis' session list, handing the pick back to home), settings, compose. Long-press a side chat to make it the main chat.
- **Goals.** A page with *Tracking* (goals with a checkbox, the latest note, cadence, next check and progress; ⋯ for open conversation / check now / pause / delete), *Routines* (OpenMinis' scheduled tasks — switch, schedule summary, run now, run records, editor, *All routines*), and *Create a goal* with seven categories. Creating one is a conversation: the sheet's *Let's go* sends an opener to the main chat with a two-turn system-prompt addendum; the model asks its questions and ends with a fenced ` ```nanomuse-goal ` block that the app turns into a goal card and a `goals.json` entry. Each goal gets its own session and a hidden interval routine that appends a one-line check to that session; the goal's context and the reporting protocol travel in that session's system prompt, and the model's ` ```nanomuse-goal-update ` block becomes a progress card and updates the row.
- **Ideas.** Twenty-four starters in six sections (`assets/nanomuse/ideas.{zh,en}.json`): emoji, pitch, what it does, and a sheet with one primary action — send to chat, create a routine (a prefilled scheduled task, editor opens), or start a goal in a category.
- **Library.** *Artifacts* and *Media* segments listing what the agent wrote under `minis-sessions/*/workspace` and `minis-global/shared`, newest first, with type icons and image thumbnails and the conversation each came from; preview through OpenMinis' file preview, share via the file provider; ⋯ opens the shared folders and the main chat's files.
- `nanomuse-*` fenced blocks render as cards in both the streaming and the static Markdown renderers.

## Changed

- The first-conversation and goal hooks now also run after *retry*, *resume* and queued prompts, not only after a plain send.
- The scheduled-task list hides goal checks; they are managed from the Goals page.
- nanoMuse's own pages use Muse's neutrals: white surfaces, a warm disc under the face, grey fills. OpenMinis' iOS-grouped scheme is left as it is for its own screens.
- versionCode 4; installs over 0.1.2 without losing data — the first existing session becomes the main chat.

## Kept, on purpose

- Session list, scheduled tasks and their editor, shared folders, file browser and preview, terminal, model groups and every settings page are unchanged and reachable from the new pages.

## Known issues

- Goal checks rely on the model answering with a ` ```nanomuse-goal-update ` block; when it does not, the conversation proceeds as usual and only the progress row stays put.
- A routine created from Ideas takes the idea's title as its name; change it in the editor that opens right after.
- The library lists at most 600 files, four directories deep, skipping dot-directories and folders such as `node_modules`.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.3-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.3-arm64.apk.sha256`.

打开是一个聊天，不是会话列表。一个主聊天、脸在最上面，旁聊收进抽屉，底部四个页签：聊天、点子、目标、资源库——Muse 在手机上的形状。OpenMinis 原有的一切都还在，只是从这几页进去。

### 新增

- **首页。** 竖屏手机上启动路由直接渲染 nanoMuse 首页：四页签的外壳，聊天页始终留在其他页签底下，切页签不丢滚动位置、不丢输入框草稿、正在输出的流也不断。平板和横屏保留 OpenMinis 的双栏布局。深链接和通知照旧在上面盖一个全屏聊天。
- **主聊天。** 第一个会话成为主聊天并被记住；App 打开就是它，点聊天页签也回到它。头部是 Muse 的：浅色圆盘上的脸、贴在下巴下面的名字胶囊、左边圆形菜单键、右边圆形 ⋯。旁聊用紧凑头部——标题、菜单、⋯——标题照旧由第一轮对话自动生成。
- **抽屉。** 名字、「主要聊天」、带搜索的旁聊列表、一个归档图标进完整的会话列表（OpenMinis 的会话列表，选中后交回首页）、设置、新建。长按旁聊可设为主要聊天。
- **目标。** 一页三段：「追踪」（勾选框、最近一条记录、节奏、下次检查、进度；⋯ 里有打开对话 / 立即检查 / 暂停 / 删除）、「例程」（就是 OpenMinis 的定时任务——开关、时间摘要、立即运行、运行记录、编辑器、「全部例程」）、「创建目标」七个分类。建目标是一段对话：底部面板的「开始吧」往主聊天发一句开场，附两轮系统提示附言；模型问完问题，末尾给一个 ` ```nanomuse-goal ` 代码块，App 把它变成目标卡片和 `goals.json` 里的一条。每个目标有自己的会话和一个隐藏的间隔例程，到点往那个会话追加一行「看看这个目标」；目标的上下文和汇报格式放在该会话的系统提示里，模型回的 ` ```nanomuse-goal-update ` 变成进度卡片并更新那一行。
- **点子。** 六组二十四条，来自 `assets/nanomuse/ideas.{zh,en}.json`：表情、一句话、它会做什么，面板里只有一个主动作——发到聊天、创建例程（预填好的定时任务，直接进编辑器）、或在某个分类下开始目标。
- **资源库。** 「构件」「影音内容」两段，列出 agent 写在 `minis-sessions/*/workspace` 和 `minis-global/shared` 里的文件，新的在前，类型图标、图片缩略图、来自哪个对话；预览走 OpenMinis 的文件预览，分享走 file provider；⋯ 里有共享文件夹和主聊天的文件。
- `nanomuse-*` 围栏代码块在流式和静态两个 Markdown 渲染器里都渲染成卡片。

### 变更

- 第一次对话和目标的钩子现在在「重试」「继续」和排队消息之后也会跑，不只是普通发送之后。
- 定时任务列表隐藏目标检查；它们在目标页管理。
- nanoMuse 自己的页面用 Muse 的中性色：白色表面、脸下面暖色圆盘、灰色填充；OpenMinis 自己的页面维持它的 iOS 分组配色。
- versionCode 4；覆盖安装 0.1.2 不丢数据，第一个已有会话自动成为主聊天。

### 有意保留

- 会话列表、定时任务和它的编辑器、共享文件夹、文件浏览和预览、终端、模型分组和所有设置页都没动，从新页面都能到。

### 已知问题

- 目标检查依赖模型按格式回一个 ` ```nanomuse-goal-update ` 块；模型不照做时对话照常进行，只是进度不更新。
- 点子里的例程用点子的标题做名字，可以在紧接着打开的编辑器里改。
- 资源库最多列 600 个文件、目录深度 4，不含以点开头的目录和 `node_modules` 之类。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。

### 安装

下载 `nanoMuse-0.1.3-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.3-arm64.apk.sha256`。
