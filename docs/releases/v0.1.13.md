# nanoMuse 0.1.13 · Reach

The phone drives your computer — a working demo. Run one Python file on the PC, type its six-digit code into the app, and from then on a sentence on the phone runs there: a command in its shell, a file fetched or dropped, a page opened in its browser, a look at its screen. The results come back to the phone, and so do the approvals — a command for the computer waits for the same card as the phone's own shell before it is sent. One way, phone to computer, for now.

## Added

- **Settings → Computers.** The computers this phone drives, each with its system, address and when it last answered — tap to check, *Forget* to drop the key. *Pair a computer* in two steps: run `python3 nanomuse_host.py` there, enter the address and the code it prints. Four lines on how it works.
- **The companion.** `host/nanomuse_host.py` — one file, Python 3, nothing to install. It prints the address and a pairing code (ten minutes, one phone), keeps only a hash of each phone's key, and answers the phone's requests on your local network. `--forget` starts over.
- **`nanomuse-pc`.** The agent's command: `run` a shell command there (with `--cwd` and `--timeout`), `ls` a folder, `get` a file into the chat (pictures show inline), `put` one there (never overwriting quietly), `open` a page in the computer's browser, `screen` for a picture of its screen, `status` for who answers.
- **The same approvals, on the phone.** A command for the computer is judged like one for the phone — deleting, sending, paying waits for your approval — and the card says *On the computer “desk”, not on this phone.* What you allow for a folder here is never carried over to the same folder there.
- **The agent knows.** With no computer paired, it explains the one-time pairing instead of pretending; with one paired, it says what it will run there and where.

## Changed

- versionCode 14; installs over 0.1.12 without losing data.

## Known issues

- No encryption between the phone and the computer yet: the key travels in clear on your local network. Use a network you trust. Certificates pinned at pairing are the next step.
- The address is typed, not discovered: if the computer's IP changes, forget and pair again.
- The computer's screen is a picture to look at, not yet a hand — mouse and keyboard on the PC come later, on the same companion.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.13-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.13-arm64.apk.sha256`. On the computer: Python 3.11 or newer, `python3 host/nanomuse_host.py`.

手机操作你的电脑——先出一个能用的 demo。在电脑上跑一个 Python 文件，把它打印的六位配对码填进 App，之后手机上的一句话就能在那边执行：在它的终端里跑一条命令、取一个或放一个文件、在它的浏览器里打开一个页面、看一眼它的屏幕。结果回到手机上，审批也在手机上——给电脑的命令和手机自己的终端一样，先过审批卡再发出去。暂时是单向的，手机到电脑。

### 新增

- **设置 → 电脑。** 这台手机能操作的电脑，各自显示系统、地址和上次响应时间——点一下检查在线，「忘记」丢掉密钥。「配对一台电脑」两步：在那边运行 `python3 nanomuse_host.py`，把它打印的地址和配对码填进来。另有四行说明它是怎么工作的。
- **电脑端。** `host/nanomuse_host.py`——一个文件，Python 3，什么都不用装。它打印地址和配对码（十分钟有效，只认一台手机），只保存每台手机密钥的哈希，在局域网里响应手机的请求。`--forget` 可以重来。
- **`nanomuse-pc`。** 它的命令：`run` 在那边跑一条命令（可带 `--cwd`、`--timeout`），`ls` 列目录，`get` 把文件取回对话（图片直接显示），`put` 放一个过去（不会悄悄覆盖），`open` 在电脑浏览器里打开页面，`screen` 拍一张它的屏幕，`status` 看谁在线。
- **同一套审批，在手机上。** 给电脑的命令和给手机的判定一样——删除、发送、付款要先经过你同意——审批卡上会写「在电脑『desk』上，不是在这台手机上」。你在这边对某个目录的「总是允许」，不会带到那边的同名目录。
- **它心里有数。** 没配对电脑时，它会解释一次性的配对步骤，不会装样子；配对了，它会说清要在哪台电脑上跑什么。

### 变更

- versionCode 14；覆盖安装 0.1.12 不丢数据。

### 已知问题

- 手机和电脑之间暂时没有加密：密钥在你的局域网里明文传输，请在信任的网络里使用。下一步是配对时固定证书。
- 地址是手填的，不是自动发现的：电脑 IP 变了就忘记再配对一次。
- 电脑屏幕现在只是给它看的一张图，还不是一双手——电脑上的鼠标键盘操作以后加在同一个程序里。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。
