# nanoMuse 0.1.5 · Memory

The agent starts to keep things: a feed it writes for you every morning; the files that make it what it is — who it is, what it knows about you, what it remembers, when it wakes — readable and editable in one place; and a way to bring over what another assistant already knew. Long tasks keep the screen on and ask "continue?" instead of wrapping up early.

## Added

- **Feed tab.** The second glyph in the bottom bar. A built-in routine — *Write the feed*, daily at 08:00, visible under Goals → Routines with its switch, editor and run records like any other — asks the agent to read `GLOBAL.md`, the last seven days of diary, `USER.md` and the goals, and write three to six short posts. Each post is a fenced ` ```nanomuse-feed ` JSON block in the feed's own side chat; the app stores every block as `minis-global/nanomuse/feed/YYYY-MM-DD/NN.md` (front matter: title, type, emoji, source, created, liked) and the tab renders them as Muse's cards on a grey canvas — weekday and part of day as the section title, a 44 dp emoji tile, title, Markdown body, heart · *Discuss* · ⓘ. *Discuss* opens a side chat titled after the post with its text as the opener; ⓘ shows type, time, sources, the file path, and a delete. The first visit shows Muse's *About the feed* card with the steering sentence and *Edit* / *Got it*; the round sliders button at the top right opens the settings sheet — the sentence (`feed-preferences.md`, quoted verbatim in the feed's system prompt), the daily switch, "Daily at 08:00 · tap to change" (opens the routine editor), *Write it now*. Twelve posts a day at most; thirty days are kept.
- **System files** (Settings → System files; also in the ⋯ menu of every tab and in the drawer). Muse's list: an `MD` badge, the file name, "MD · 358 B · 03:13", sort by name or by last modified, ⋮ to copy or share. Opening a file gives Muse's page: round back button, the name, a pill with the pencil and ⋯, an italic *About this file* quote, and the file rendered as Markdown. Five files: `SOUL.md` (the persona — saving refreshes the cached soul), `USER.md` (new — what the agent knows about you), `GLOBAL.md` (the memory; ⋯ jumps to OpenMinis' memory pages for the diary), `feed-preferences.md`, and `HEARTBEAT.md` — a read-only view of every routine and goal check with schedule and last run, with a ♥ badge. Edits use a monospace editor with a hint, Cancel and a blue Save.
- **USER.md in the system prompt.** When the file has content it is appended after the memory fragments, with one paragraph telling the model to keep it current from its shell (`/var/minis/memory/USER.md`) and never to put passwords or other secrets in it. The file lives next to `GLOBAL.md` and `SOUL.md` in `minis-global/memory/` so the agent can reach it.
- **Import memory** (System files → ⋯ → Import memory). One page: the prompt to give your other assistant ("gather everything you remember about me into bullet points…") with a copy button, a *From* field, a paste box, and *Add to memory*, which appends `### <date> · <from>` and the text under an `## Imported` section at the end of `GLOBAL.md` (created if missing; recognised in English and Chinese).
- **Finished browser steps keep their picture.** The last live frame of the in-app browser is remembered per tool block and shown when the step saved no screenshot of its own; the floating status bar reads "Open test page · Done" for a completed `browser_use` step. The two levels of status stay: the running tool's title under the face, the action chips on the cards.
- **The screen stays on** while the agent drives the in-app browser or another app through the accessibility service. Ordinary chat and shell work let it time out as usual.
- **"Still going after 200 steps."** When the agent loop reaches its step limit it no longer writes an error into the chat; a card above the composer asks whether to keep going — *Continue* resumes from where it stopped, *Stop here* leaves OpenMinis' Resume banner in place. The card is cleared when you send, retry, clear the chat or switch sessions.
- `nanomuse-feed` blocks render as a small "Added to the feed" card with an *Open* button in the conversation where they were written.

## Changed

- Every completed turn is also handed to the feed parser; the system prompt gains the `USER.md` paragraph and, in the feed's session only, the feed protocol and a digest of the memory files and goals (≤ 7 000 characters).
- nanoMuse log categories no longer double the `nanoMuse.` prefix.
- versionCode 6; installs over 0.1.4 without losing data.

## Kept, on purpose

- OpenMinis' memory pages (`GLOBAL.md` + diary) and the soul editor are unchanged; the system files pages open them for the parts they cover. The feed routine is an ordinary scheduled task — pause, edit or delete it like any other.

## Known issues

- The feed relies on the model following the protocol and emitting JSON blocks; a weak model may write fewer posts or malformed ones, and malformed blocks are ignored rather than reported. *Write it now* runs it again.
- The 08:00 routine depends on the system alarm; devices that restrict background work may fire it late.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.5-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.5-arm64.apk.sha256`.

### 新增

- **动态页签。** 底栏第二个图标。内置一条例程「写动态」，每天 08:00 跑，在 目标 → 例程 里能看到，开关、编辑、运行记录和别的例程一样。它让 agent 读 GLOBAL.md、近七天日记、USER.md 和目标，写 3–6 条短帖。每条帖子是「动态」旁聊里的一段 ` ```nanomuse-feed ` JSON；App 把每段存成 `minis-global/nanomuse/feed/YYYY-MM-DD/NN.md`（frontmatter：标题、类型、emoji、来源、时间、是否收藏），页签按 Muse 的样子渲染：灰底、「周五上午」做节标题、44 dp 的 emoji 方块、标题、Markdown 正文，底部 ♥ · 讨论 · ⓘ。「讨论」新开一条以帖子为题的旁聊，帖子内容作开场；ⓘ 看类型、时间、来源、文件路径，可删除。第一次进来是 Muse 的「动态版块说明」卡片：一句指示，「编辑」/「知道了」。右上角圆形滑杆按钮打开设置：那句指示（`feed-preferences.md`，会原文引进动态会话的系统提示）、每日开关、「每天 08:00 · 点击修改」（进例程编辑器）、「现在写一版」。每天最多 12 条，保留 30 天。
- **系统文件**（设置 → 系统文件；每个页签的 ⋯ 菜单和抽屉里也有）。Muse 的列表：`MD` 徽标、文件名、「MD · 358 B · 03:13」，按名称或最近修改排序，⋮ 复制 / 分享。打开是 Muse 的文件页：圆形返回、文件名、铅笔 + ⋯ 的胶囊、斜体的「关于这个文件」引文、Markdown 渲染的正文。五个文件：`SOUL.md`（人格，保存后刷新缓存）、`USER.md`（新：它知道的关于你的事）、`GLOBAL.md`（记忆；⋯ 可跳到 OpenMinis 的记忆页看日记）、`feed-preferences.md`、`HEARTBEAT.md`（只读：所有例程和目标检查的时间与上次运行，♥ 徽标）。编辑是等宽编辑器，带提示、取消和蓝色保存。
- **USER.md 进系统提示。** 文件有内容时接在记忆片段之后，附一段话让模型从 shell（`/var/minis/memory/USER.md`）持续维护它、绝不写入密码等敏感信息。文件放在 `minis-global/memory/`，和 `GLOBAL.md`、`SOUL.md` 一起，agent 能碰到。
- **导入记忆**（系统文件 → ⋯ → 导入记忆）。一页：给别的助手的提示词（「请把你记住的关于我的信息整理成要点……」）和复制按钮、「来自」、粘贴框、「追加到记忆」。追加为 `### 日期 · 来自` 加正文，放在 `GLOBAL.md` 末尾的 `## 导入` 节下（没有就建，中英文标题都认）。
- **浏览器步骤完成态。** 应用内浏览器的最后一帧按工具卡片记住，步骤没存截图时用它；完成的 `browser_use` 步骤在浮动状态栏里显示「打开测试页 · 已完成」。两级状态照旧：头像下是正在跑的工具标题，卡片上是动作 chips。
- **屏幕常亮。** agent 在开应用内浏览器或通过无障碍服务操作别的 App 时屏幕不灭。普通聊天和 shell 照常超时。
- **「已经跑了 200 步」。** agent 循环到步数上限时不再往聊天里写错误，而是在输入框上方出一张卡片问要不要继续——「继续」从断点接着跑，「先停在这里」留着 OpenMinis 原来的 Resume 横幅。发送、重试、清空、切换会话都会收掉这张卡。
- 对话里写出的 `nanomuse-feed` 段渲染成一张小卡片「已加入动态」，带「打开」。

### 变更

- 每个完成的回合也交给动态解析器；系统提示追加 USER.md 段，且只在动态会话里追加动态协议和一份 ≤ 7000 字的记忆 / 目标摘要。
- nanoMuse 日志分类不再重复 `nanoMuse.` 前缀。
- versionCode 6；覆盖安装 0.1.4 不丢数据。

### 有意保留

- OpenMinis 的记忆页（GLOBAL.md + 日记）和人格编辑器没动，系统文件页会跳到它们负责的部分。动态例程就是一条普通定时任务，可以像别的例程一样暂停、编辑、删除。

### 已知问题

- 动态靠模型按协议输出 JSON 段；弱模型可能少写或写错格式，写错的段会被忽略而不是报错。用「现在写一版」再试一次即可。
- 例程在 08:00 触发依赖系统闹钟；被系统限制后台的机器可能推迟。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。

### 安装

下载 `nanoMuse-0.1.5-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.5-arm64.apk.sha256`。
