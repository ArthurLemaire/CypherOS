# nanoMuse 0.1.2 · Identity

The agent gets a face and a name, and the first conversation is where you meet it — the shape of Muse's first run, on top of OpenMinis' setup cards, which are unchanged.

## Added

- **The red panda in the chat header.** Above the name, 36 dp, drawn from the same shapes as the web mascot. Its mood follows the session: idle; working (breathing, narrowed eyes) while the model streams; waiting (round mouth) when an approval, a permission or a config confirmation is pending; happy for three seconds after a turn; sorry for four after a failure. Tap it — or the name pill under it — to open Settings → Soul and change the name, icon and style.
- **Muse's header.** The name sits in a capsule under the face; while the agent works, the model rows give way to a status line — the running tool's title, "Thinking…", or "Waiting for you" in the accent colour — and come back when it is idle.
- **The first conversation.** With no sessions yet and the default name still in place, the first chat opens with a scripted greeting, how the agent works and "what should I call you?". Your reply is saved as your form of address in `GLOBAL.md` (`## About the user`); the model confirms in one sentence and asks for its own name, and a chooser card appears under that message — two suggestions and *Something else…*, the composer's placeholder turning into "Write a name here". A pick or a typed name goes straight into `SOUL.md` (no `minis-config` round-trip, no confirmation dialog); the header, the message labels and the placeholder rename at once, and the model's next reply — one line about the name, three concrete things it can do on this phone, "what first?" — is steered by a system-prompt addendum that exists only for those two turns. The opening and the card are pure UI rows: never in the database, never in the history a provider sees (Anthropic rejects a transcript that opens with the assistant). The opening is drawn again when the first session is reopened.
- **The name everywhere.** Notifications carry the face as their large icon and the Soul name as sender: the foreground service ("<name> is working"), background results, scheduled tasks, alarms, config confirmations, and the notifications the agent sends itself; the browser banner reads "<name> is browsing". Both are applied by `scripts/rebrand.py`, so an upstream pull keeps them.
- **CI**: `.github/workflows/android.yml` builds a debug arm64 APK on ubuntu-24.04 for pushes and pull requests that touch the Android tree and uploads it as an artifact. No signing, no secrets.
- `-Pnm.abi=x86_64` builds a chat-only test APK for the x86_64 emulator (the sandbox payloads are arm64-only).

## Changed

- The chat top bar no longer shows the session title; *Rename chat* moved to the ⋮ menu, and the Appearance switch *Show chat title* is gone (its `minis-config` key remains, inert).
- Copy in nanoMuse's voice for the welcome card, the onboarding subtitle and the service notification (en, zh, zh-TW; other locales keep upstream's wording). The Korean locale had 30 strings still reading "Minis" — `rebrand.py` now catches the particle-suffixed form.
- versionCode 3; installs over 0.1.1 without losing data.

## Kept, on purpose

- The provider list and its OAuth sign-ins (Claude, Codex, Kimi, OpenRouter) and the three setup cards stay as in OpenMinis 1.13. There are no vendor presets for Chinese providers yet; use *OpenAI / compatible API* with your own base URL and key.

## Known issues

- The name chooser appears once, in the first conversation. Later renames go through Settings → Soul, or by asking the agent (it uses `minis-config`).
- Reopening the first session brings the opening back but not the chooser — the choice already lives in `SOUL.md`.
- Approval scopes, Muse's four tabs and readable, editable memory are still on the roadmap, one per version. Chinese services (飞书, 高德, 快递100…) do not get a version of their own: the shell, MCP and skills in the sandbox already reach them from a sentence in the chat.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.2-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.2-arm64.apk.sha256`.

nanoMuse 有了脸和名字，第一次对话就是认识它的地方——Muse 首次运行的形态，搭在 OpenMinis 的三张设置卡之上（三张卡没有动）。

### 新增

- **聊天页头部的小熊猫。** 名字上方 36 dp，和网页版吉祥物出自同一套形状。表情跟着会话走：空闲、工作中（模型输出时呼吸、眯眼）、等你（有审批 / 权限 / 配置确认待处理时圆嘴）、一轮结束后开心三秒、失败后皱眉四秒。点头像或名字胶囊，进「设置 → Soul」改名字、图标、风格。
- **Muse 的头部。** 名字放在脸下面的胶囊里；干活时模型那两行让位给状态行——正在跑的工具名、「思考中…」、或强调色的「等你确认」——空下来再换回来。
- **第一次对话。** 没有任何会话、名字还是默认值时，第一个聊天以脚本开场：打招呼、它怎么工作、「我该怎么称呼你」。你的回答存进 `GLOBAL.md`（`## About the user`）作为称呼；模型一句话确认、再问自己叫什么，那条消息下面出现起名卡——两个候选加「自己取一个…」，输入框提示变成「写个名字…」。点一个或自己敲一个，直接写进 `SOUL.md`（不经 `minis-config`，不弹确认），头部、消息署名、输入框提示立刻改名；模型的下一句——一句话说名字、三条它在这台手机上能立刻做的事、「先试哪个」——由只存在两轮的系统提示附言引导。开场白和起名卡是纯界面消息：不进数据库，也不进发给模型的历史（Anthropic 拒绝以 assistant 开头的对话）。重开第一个会话时开场白会再画出来。
- **名字贯穿。** 通知以小熊猫为大图标、以 Soul 名字为发件人：前台服务（「阿福 正在工作」）、后台结果、定时任务、闹钟、配置确认、agent 自己发的通知；浏览器横幅是「阿福 正在浏览」。这两处走 `scripts/rebrand.py`，上游同步后不丢。
- **CI**：`.github/workflows/android.yml` 在 ubuntu-24.04 上为触及 Android 目录的 push / PR 打 debug arm64 包并上传 artifact。不签名、不碰任何密钥。
- `-Pnm.abi=x86_64` 打一个只有聊天的 x86_64 模拟器测试包（沙盒的原生文件只有 arm64）。

### 变更

- 聊天顶栏不再显示会话标题；「重命名对话」挪进 ⋮ 菜单，外观里的「显示聊天标题」开关去掉（`minis-config` 键保留，不再起作用）。
- 欢迎卡、引导副标题、服务通知用 nanoMuse 的口吻重写（en / zh / zh-TW，其他语言沿用上游）。韩语还有 30 条写着 Minis，`rebrand.py` 现在能抓到带助词的形式。
- versionCode 3；覆盖安装 0.1.1 不丢数据。

### 有意保留

- 服务商列表及其中的 OAuth 登录（Claude / Codex / Kimi / OpenRouter）、三张设置卡与 OpenMinis 1.13 一致；暂无国内厂商预设，用「OpenAI / 兼容 API」填自己的 base URL 和 key。

### 已知问题

- 起名卡只在第一次对话里出现一次；之后改名走「设置 → Soul」或让它自己 `minis-config`。
- 重开第一个会话时开场白会回来，起名卡不会（选择结果已在 `SOUL.md` 里）。
- 审批范围、Muse 的四个页签、可读可改的记忆仍在路线图上，一版一个。国内服务（飞书 / 高德 / 快递100 …）不单出版本：沙盒里的 shell、MCP、技能已经够用，聊天里说一句就行。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。

### 安装

下载 `nanoMuse-0.1.2-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.2-arm64.apk.sha256`。
