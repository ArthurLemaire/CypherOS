# nanoMuse 0.1.12 · Hands

The phone's screen as a hand — a working demo. For the apps that never had an API, the agent can now use the phone the way you do: it looks at a screenshot, decides one action, taps, types or swipes, and looks again. It sees the screenshot alone — no accessibility tree — and the accessibility service is only the hand that takes the picture and performs the gesture. A capsule at the top of the screen shows each step with **Stop**. Logins, passwords and codes are yours to type. A tap that pays, sends, posts or deletes waits for the same approval card as the shell and the browser. Off by default.

## Added

- **Settings → Hands.** The switch (off until you turn it on), the three things it needs — the accessibility service, display over other apps, a model that sees pictures — each with the button that takes you to the right setting, the screen model (automatic, or one of your vision models), and five lines on how it behaves.
- **The ladder.** The agent is told to try a skill, a command or an MCP server first, then the page with your login or the browser, and the screen last — and to say which rung it is on before it starts. With the hands off, it says so and links the setting instead of pretending.
- **`nanomuse-hands`.** The agent's command: `run --task "…" [--app "…"]` works the task on the screen and returns the result, the number of steps and the last screenshot, which it can show you inline; `apps` lists what is installed; `status` says what is set up.
- **Take-over and approvals.** A login, a password, a code, a captcha, a face or fingerprint check, or a protected (black) page: the capsule says *Your turn*, you do that part and tap **Continue**. A button whose label says pay, order, transfer, send, post, delete: the approval card appears in nanoMuse (and as a notification), the capsule offers **Open**, and a refusal ends the run rather than letting it look for another button.
- **A trace.** Every step's screenshot and the model's thought are kept with the conversation under `attachments/hands/<run>/`, sent only to your own model.

## Changed

- versionCode 13; installs over 0.1.11 without losing data.
- *Unsubscribe* in the browser is no longer read as a subscription when the approval card is decided.

## Known issues

- This is a demo built and unit-tested, not yet driven on a phone by us: expect rough edges. It needs Android 11 or newer.
- Pages that forbid screenshots (payment, banking) are black to the model and handed to you.
- Typing uses the system's set-text action on the focused field; some custom keyboards and web views ignore it, and the model is told to tap the field and try again.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.12-arm64.apk` (Android 8.0 or newer, arm64; the hands need Android 11) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.12-arm64.apk.sha256`.

手机屏幕当手——先出一个能用的 demo。对于那些从来没有接口的 App，它现在可以像你一样用手机：看一眼截图，决定一步，点、输或者滑，再看一眼。它只看截图，不读无障碍树；无障碍服务只负责截图和手势。屏幕顶部有一个胶囊，显示每一步和「停止」。登录、密码、验证码永远由你自己输。付款、发送、发布、删除的那一下，和命令行、浏览器一样先经过审批卡。默认关闭。

### 新增

- **设置 → 动手操作屏幕。** 开关（默认关，需要你亲自打开），它需要的三样东西——无障碍服务、显示在其他应用上层、一个能看图的模型——每一项都带一个跳到对应设置的按钮；看屏幕的模型（自动，或你的某个视觉模型）；还有五行说明它会怎么做。
- **梯子。** 它被告知先试技能、命令行、MCP 服务，再试带你登录态的网页或浏览器，最后才是屏幕——而且动手前先说自己在哪一级。开关没开时，它会直说并给出设置链接，不会装样子。
- **`nanomuse-hands`。** 它的命令：`run --task "…" [--app "…"]` 在屏幕上把任务做完，返回结果、步数和最后一张截图（可以直接贴给你看）；`apps` 列出装了哪些 App；`status` 说明配置情况。
- **接管与审批。** 登录、密码、验证码、图形验证、人脸或指纹、受保护的黑屏页面：胶囊变成「轮到你了」，你做完这一步点「继续」。按钮文字带付款、下单、转账、发送、发布、删除的：审批卡出现在 nanoMuse 里（也有通知），胶囊上提供「打开」；你拒绝，这次运行就结束，不会去找别的按钮。
- **留痕。** 每一步的截图和模型的想法随对话保存在 `attachments/hands/<run>/` 下，只发给你自己的模型。

### 变更

- versionCode 13；覆盖安装 0.1.11 不丢数据。
- 浏览器里的 Unsubscribe 不再被当成订阅来判定审批。

### 已知问题

- 这是一个写完并跑过单元测试、还没在真机上跑过的 demo，会有毛边。需要 Android 11 或更新。
- 禁止截图的页面（支付、银行）对模型来说是黑的，会交给你。
- 输入用的是系统对焦点输入框的 set-text 动作，部分自定义键盘和网页视图不认，模型会被提示先点一下输入框再试。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。
