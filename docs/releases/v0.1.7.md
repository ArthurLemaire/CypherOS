# nanoMuse 0.1.7 · Welcome

The first run is back, in Muse's shape. A fresh install opens on a welcome screen — the mark, three steps, one blue button — instead of a chat that cannot answer: add a model provider, pick from the models it actually serves, meet the agent. The steps are OpenMinis' own provider and model screens, so the models are detected from your provider the way they were in 0.1.2.

## Fixed

- **The setup had disappeared on phones.** 0.1.3's home replaced the session list, and with it the three-step setup OpenMinis shows before the first conversation. A fresh install of 0.1.3–0.1.6 opened straight into the main chat with no provider configured: the greeting asked what to call you, the reply failed with "No provider configured", and the only way to a provider was Settings in the drawer. The welcome screen brings the setup back and hands step 2 to OpenMinis' *Select Models*, which refreshes each provider's catalogue and lists it for you.
- **The first conversation now uses the model you chose.** The main chat's ViewModel is no longer built before the setup is over; one built earlier kept whichever model entry it had found first.

## Added

- **Welcome screen.** The N mark, "Welcome to nanoMuse", and the three steps as rows — done (check), current (blue number, chevron), locked ("After step 1") — with a blue *Continue* that performs the next step and reads *Start* on the last; *Skip for now* on step 2; the fine print that your key stays on the phone, with *Learn more*; a gear to Settings at the top right, as on Muse's own welcome. Shown until *Start*; it comes back whenever the app has no provider at all; an install that already has conversations never sees it.
- English, Chinese and Traditional Chinese strings; four unit tests for the gate.

## Changed

- versionCode 8; installs over 0.1.6 without losing data.

## Known issues

- An install that already has a provider but has never started a conversation sees the welcome once, with the finished steps checked — tap *Start*.
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.7-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.7-arm64.apk.sha256`.

第一次运行回来了，而且是 Muse 的样子。新装的 App 打开是一个欢迎页——标记、三步、一个蓝色按钮——而不是一个答不了话的聊天：添加模型服务商、从它实际提供的模型里挑、认识它。三步用的是 OpenMinis 自己的服务商页和选模型页，所以模型是从你的服务商自动识别出来的，和 0.1.2 时一样。

### 修复

- **手机上的引导页不见了。** 0.1.3 的首页替掉了会话列表，也把 OpenMinis 在第一次对话之前的三步引导一起替掉了。0.1.3–0.1.6 新装后直接进主聊天、没有任何服务商：开场白问你叫什么，回复报「No provider configured」，唯一能配服务商的地方是抽屉里的设置。欢迎页把引导找回来，第二步交给 OpenMinis 的「选择模型」——它会刷新每个服务商的模型目录并列出来。
- **第一次对话用的是你选的模型。** 主聊天的 ViewModel 不再在引导结束前创建；之前创建的会一直用它最先找到的那个模型条目。

### 新增

- **欢迎页。** N 标记、「欢迎使用 nanoMuse」、三步做成行——已完成（对勾）、当前（蓝色数字、箭头）、锁定（「先完成第 1 步」）——底部蓝色「继续」执行下一步，最后一步显示「开始」；第二步有「先跳过」；小字说明 key 只留在手机上，附「了解更多」；右上角齿轮进设置，和 Muse 自己的欢迎页一样。直到点「开始」之前一直显示；App 完全没有服务商时会再出现；已经有对话的安装永远不会看到它。
- 英文、简体、繁体字符串；4 个单元测试覆盖判断逻辑。

### 变更

- versionCode 8；覆盖安装 0.1.6 不丢数据。

### 已知问题

- 已经配了服务商但从没开始过对话的安装会看到一次欢迎页，完成的步骤打了勾——点「开始」即可。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。

### 安装

下载 `nanoMuse-0.1.7-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.7-arm64.apk.sha256`。
