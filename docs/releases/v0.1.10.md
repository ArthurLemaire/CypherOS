# nanoMuse 0.1.10 · Motion

The face moves, and the three models are named. Muse has its image and video models built in; nanoMuse runs on three of your own — the chat model you talk to, an image model that draws the avatar and pictures you ask for, a video model that makes the avatar move and short clips — and now says so in one place, in the settings and in the conversation. With a video model set, the avatar gets a short looping clip for each state. Without one, nothing breaks: the agent tells you what is missing and where to set it.

## Added

- **Settings → Image & video models.** One page for the three models. The chat model is your default group. For the image model, pick a provider among those that can draw and type or tap a model name (qwen-image-3.0 on Alibaba Cloud Model Studio, gpt-image-1 on OpenAI, anything with the OpenAI images endpoint); the page says *Ready*, *Not set* or *Type a model name below*, and what stops working without it. The video model is optional: a provider on Alibaba Cloud Model Studio with `MiniMax/MiniMax-H3`, a switch to animate the avatar after every change, and a row for the current face's clips — how many of the four exist, *Make* or *Redo*, and the stage while it draws. The Settings list shows the row with *Not set* until an image model is usable.
- **The moving avatar.** Once a new face is adopted and its poses are drawn, four 4-second clips are made in the background, one per state, each from that state's pose: a head shake and a gentle sway at rest, a crystal ball while it waits for you, a five-pointed star when pleased, headphones and a laptop while it works. The header and the studio play the current state's clip in a loop inside the same circle, muted, and show the still pose wherever there is no clip yet. The status line reads *Animating 1/4…* meanwhile. Clips go with the face they belong to.
- **Pictures and clips on request.** Ask the agent for a picture or a short clip for any other purpose — a sticker, a card, an illustration for a note — and it makes it through the same two models with the `nanomuse-media` command in its sandbox; the result appears in the chat. If the model needed is not set, it says so and links the setting.
- **The agent knows its three models.** Which are set and which are not is part of what it is told each turn, so when you ask it to change its look or draw something without an image model, the answer comes from the agent, in your language — changing its look needs an image model on one of your providers, unlike Muse this is something you set up yourself, here is the setting — instead of from a fixed message.

## Changed

- An image model counts as set only when it has a provider with a key *and* a model name; a provider the catalogue does not know asks for the name instead of showing *Not set*.
- The image-model sheet in the avatar studio is gone; its entries open the new page.
- versionCode 11; installs over 0.1.9 without losing data.

## Not in this version

- The bundled default face is still the red panda; three Muse-like candidates have been drawn and one will replace it, with its poses and clips, in the next version.
- Video generation speaks Alibaba Cloud Model Studio's API only. MiniMax-H3 has to be activated once on its model card in the Model Studio console; until then the task fails with a plain "not activated" message and the avatar stays still.

## Known issues

- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.
- Clips are made one after another and each takes one to a few minutes on the provider's side; leaving the app in the middle stops the run, and *Redo* on the clips row starts it again.
- Model Studio rate-limits image requests on new accounts; the four candidates are drawn two at a time with retries, but a second request in the same minute can still be refused.

## Install

Download `nanoMuse-0.1.10-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.10-arm64.apk.sha256`.

脸动起来了，三个模型也说清楚了。Muse 的图像和视频模型是官方自带的；nanoMuse 跑在你自己的三个模型上——和你对话的对话模型、画形象和你要的图片的图像模型、让形象动起来和生成短片的视频模型——现在在设置里、在对话里都讲明白了。设好视频模型，形象的每个状态都有一段循环短片。没设也不会坏：它会告诉你缺什么、去哪里设。

### 新增

- **设置 → 图像与视频模型。** 三个模型一页说清。对话模型就是你的默认模型组。图像模型：在能画图的服务商里选一个，填或点一个模型名（阿里云百炼的 qwen-image-3.0、OpenAI 的 gpt-image-1、任何有 OpenAI images 接口的服务商）；页面会显示「就绪」「未设置」或「在下方填写模型名」，并说明没有它什么用不了。视频模型可选：阿里云百炼的服务商加 `MiniMax/MiniMax-H3`，一个「换形象后自动生成动态」的开关，以及当前形象短片的一行——四段里有几段、「生成」或「重做」、生成时的进度。图像模型可用之前，设置列表里这一行显示「未设置」。
- **会动的形象。** 换上新脸、姿势画完后，后台接着做四段 4 秒的短片，每个状态一段、以该状态的姿势作首帧：待机时摇头轻晃，等你时玩水晶球，开心时玩五角星，工作时戴耳机敲电脑。页头和形象工作室在同一个圆里循环静音播放当前状态的短片，没短片的状态仍显示静态姿势。期间状态线显示「正在生成动态 1/4…」。短片跟着所属的脸一起清除。
- **按需生图、生视频。** 让它画一张图或做一段短片用在别处——贴纸、卡片、笔记配图——它通过沙盒里的 `nanomuse-media` 命令用同样的两个模型来做，结果直接出现在对话里。需要的模型没设时，它会说明并附上设置的链接。
- **它知道自己的三个模型。** 哪些设了、哪些没设，每一轮都会告诉它，所以没有图像模型时你让它换形象或画图，回答来自它本人、用你的语言——换形象需要某个服务商上有图像模型，和 Muse 不同这是你自己设置的，设置在这里——而不是一句写死的提示。

### 变更

- 图像模型只有同时具备带 key 的服务商和模型名才算已设置；目录里不认识的服务商会提示填模型名，而不是显示「未设置」。
- 形象工作室里的图像模型面板去掉了，入口都指向新页面。
- versionCode 11；覆盖安装 0.1.9 不丢数据。

### 这版没有

- 内置默认脸仍是小熊猫；三个 Muse 风格的候选已画出，下一版选定一个替换，连带姿势和短片。
- 视频生成目前只对接阿里云百炼的接口。MiniMax-H3 需要在百炼控制台的模型卡片上开通一次；开通前任务会以一句直白的「未开通」失败，形象保持静态。

### 已知问题

- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。
- 短片是一段接一段生成的，每段在服务商那边要一到几分钟；中途离开应用会中断，短片那一行的「重做」可以重来。
- 百炼对新账号的图像请求有频率限制；四张候选两张两张地画并会重试，但同一分钟内再发请求仍可能被拒。

### 安装

下载 `nanoMuse-0.1.10-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.10-arm64.apk.sha256`。
