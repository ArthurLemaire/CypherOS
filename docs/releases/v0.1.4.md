# nanoMuse 0.1.4 · Guardrails

Before it deletes your files, sends something out or pays, the agent stops and asks — in the shell and in the browser. What you approve can be remembered for the rest of a chat, or for good per recipient, host or folder. Passwords and verification codes are never typed by the agent; the browser is handed to you instead.

## Added

- **Shell guard.** Every `shell_execute` command is classified before it runs: *destructive* (`rm` outside scratch directories, `find -delete`, `shred`, `truncate`, `git reset --hard` / `clean -f` / `checkout --` / `branch -D`, `gh repo delete`…), *outbound* (`git push`, `curl` / `wget` with a body or a writing method, `ssh` / `scp` / `rsync` / `nc`, mail clients, `lark-cli` write verbs, `gh` writes, cloud CLIs, package publishing, anything named like a sender), *money* (an outbound command that mentions paying, ordering or transferring), *install* (`apk` / `apt` / `pip` / `npm i` / `cargo install`…) and *safe*. Pipelines, `&&` / `;` chains, `sudo` / `env` / `nohup` wrappers, heredocs and inline `sh -c` / `python -c` scripts are judged part by part; deleting under `/tmp`, `/var/tmp` and `/dev/shm` is free. Each classification carries an *object*: the folder (the workspace, a shared folder, or the first two path components), the host, the remote, the chat id, the recipient.
- **Approval card.** Destructive, outbound and money commands suspend the tool call and slide a card in above the composer, Muse's way: icon, "Allow Spark to delete in the workspace?", one line of what it means, the command in a grey preview box, and four buttons — *Allow once* · *Allow for this chat* · *Always allow for the workspace* · *Deny*. The chat behind it dims; the status under the face reads *Needs approval*. Alarming shapes — wiping a whole tree, `dd` / `mkfs`, `curl | sh`, `chmod 777`, force push, fork bombs — get a warning card with only *Allow once* and *Deny*. Payments are asked about every time; there is no remembered approval for money. Three minutes without an answer count as a denial.
- **Remembered approvals.** *Allow for this chat* covers the same class for the rest of that conversation and is dropped when the chat is cleared or deleted; *Always allow* is persisted per class + object in `minis-global/nanomuse/grants.json`. Settings → Permissions gets a *nanoMuse remembered approvals* section listing each standing grant with its date; tapping one revokes it, and the agent asks again next time.
- **Browser guard.** Before `browser_use` clicks or types, the target element is described in-page. A tap whose text or label reads like paying, ordering, sending, deleting, publishing or confirming a purchase asks first — the card shows the button text and the page URL, and *Always allow* binds to the host. Typing into a password field or a one-time-code field (`autocomplete`, name, id, placeholder, label, a 4–8 digit numeric box, CVV) is refused outright: the tool result tells the model the field is yours to fill, and the in-app browser is brought to the front on that page.
- **Background approvals.** If the app is in the background while a card is pending, a high-priority notification carries the same title and description with *Allow once* and *Deny* actions; tapping it opens that chat. Answering anywhere dismisses the notification.
- **A policy paragraph in the system prompt**: what the app stops for, that the model should not ask twice, that a denial must not be retried or routed around, that passwords and codes are never typed, and that installs run with a one-line mention afterwards.
- 23 unit tests cover the shell and browser classifiers.

## Changed

- `executeShellCommand` runs the gate first; a denied command returns the denial to the model as the tool result and marks the tool card failed. Installs run without asking and append a one-line notice to the result.
- versionCode 5; installs over 0.1.3 without losing data.

## Kept, on purpose

- OpenMinis' own confirmation for `minis-config` settings changes and its per-category tool permissions are untouched; nanoMuse's grants sit above them on the Permissions page.

## Known issues

- Classification is rule-based, not model-based: a sending program the rules have never seen passes as safe, and a read-only command with `send` in its name is asked about once too often. Please file an issue with the command if you find a miss.
- The browser guard covers `browser_use` clicks and typing only; JavaScript the model writes itself does not pass through it (the system prompt forbids that detour).
- arm64 only; for an x86 emulator, build a test APK yourself with `-Pnm.abi=x86_64`.

## Install

Download `nanoMuse-0.1.4-arm64.apk` (Android 8.0 or newer, arm64) and install it over the previous version — same signing key, your data is kept. Verify: `sha256sum -c nanoMuse-0.1.4-arm64.apk.sha256`. Background approvals need notifications to be allowed for nanoMuse.

删东西、发消息、付钱之前，它会停下来问你——shell 里和浏览器里都是。问过的可以记住：这次对话都行，或者对这个群 / 这个域名 / 这个目录永远行。密码和验证码它永远不碰，浏览器交到你手上，你自己输。

### 新增

- **Shell 守卫。** 每条 `shell_execute` 命令执行前先分类：**删**（工作区之外的 `rm`、`find -delete`、`shred`、`truncate`、`git reset --hard` / `clean -f` / `checkout --` / `branch -D`、`gh repo delete`……）、**发**（`git push`、带请求体或写方法的 `curl` / `wget`、`ssh` / `scp` / `rsync` / `nc`、邮件客户端、`lark-cli` 的写操作、`gh` 的写操作、云厂商 CLI、发布包、任何名字像「发送」的程序）、**付**（提到付款 / 下单 / 转账的外发命令）、**装**（`apk` / `apt` / `pip` / `npm i` / `cargo install`……）和安全。管道、`&&` / `;` 串联、`sudo` / `env` / `nohup` 包装、heredoc、行内 `sh -c` / `python -c` 脚本逐段判断；`/tmp`、`/var/tmp`、`/dev/shm` 里随便删。每次分类都带一个「对象」：目录（工作区、共享文件夹、或路径的前两级）、主机、远端、群 id、收件人。
- **审批卡片。** 删、发、付三类命令会挂起工具调用，在输入框上方滑出一张卡片，Muse 的样子：图标、「允许 Spark 在工作区里删除吗？」、一行说明、灰底框里的命令，四个按钮——**允许一次** · **本次对话都允许** · **对「工作区」总是允许** · **拒绝**。卡片后面的聊天压暗，头像下面的状态变成「需要你批准」。危险形状——整棵目录树、`dd` / `mkfs`、`curl | sh`、`chmod 777`、强推、fork 炸弹——只给「允许一次」和「拒绝」。付钱每次都问，不存在「记住付款」。三分钟不回答按拒绝处理。
- **记住的授权。** 「本次对话都允许」覆盖这个会话里同一类的后续命令，清空或删除会话时一起清掉；「总是允许」按 类别 + 对象 持久化到 `minis-global/nanomuse/grants.json`。设置 → 权限 新增「nanoMuse 记住的授权」一段，列出每条长期授权和日期，点一下即可撤销，下次会重新问。
- **浏览器守卫。** `browser_use` 点击或输入之前，先在页面里描述目标元素。按钮文字或标签像「支付 / 下单 / 发送 / 删除 / 发布 / 确认购买」的点击先问——卡片显示按钮文字和页面地址，「总是允许」绑定到域名。往密码框、验证码框（`autocomplete`、name、id、placeholder、label、4–8 位数字码框、CVV）里输入直接拒绝：工具结果告诉模型这一格由用户来填，同时把应用内浏览器带到前台停在那一页。
- **后台审批。** 卡片等待时如果 App 在后台，会发一条高优先级通知，标题和说明同卡片，带「允许一次」「拒绝」两个动作；点通知打开那个会话。在任何一处作答，通知都会撤掉。
- **系统提示里的策略段。** 告诉模型 App 会在哪些地方停下来、不必再自己问一遍、被拒绝后不能重试也不能绕路、永远不输密码和验证码、装软件事后一句话提一下。
- 23 个单元测试覆盖 shell 与浏览器分类器。

### 变更

- `executeShellCommand` 先过守卫；被拒绝的命令把拒绝原因作为工具结果返回给模型，工具卡片标为失败。装软件不问，结果末尾附一行提示。
- versionCode 5；覆盖安装 0.1.3 不丢数据。

### 有意保留

- OpenMinis 自己对 `minis-config` 改设置的确认和按分类的工具权限都没动；nanoMuse 的授权放在权限页它们的上面。

### 已知问题

- 分类靠规则不靠模型：没见过的发送程序会被当成安全命令放过，反过来名字带 `send` 的读操作会多问一次。发现漏判请提 issue 附上命令。
- 浏览器守卫只看 `browser_use` 的点击和输入；模型自己写 JavaScript 操作页面不经过守卫（系统提示明确禁止这样绕路）。
- 只有 arm64 包；x86 模拟器请自行用 `-Pnm.abi=x86_64` 打测试包。

### 安装

下载 `nanoMuse-0.1.4-arm64.apk`（Android 8.0+，arm64），覆盖安装，同一把签名，数据保留；校验：`sha256sum -c nanoMuse-0.1.4-arm64.apk.sha256`。后台审批通知需要允许 nanoMuse 发通知。
